Getting started

  1. Open Content in the sidebar to browse folders. Select a folder name to open it; use the breadcrumb above the page to go back to a parent folder.
  2. Select a document name to open its information page. It shows the owner, current version, status, and the actions you can perform.
  3. Open My Documents to find your documents and items awaiting your review or approval.
  4. Use the top search bar to find documents. The Help entry opens this guide; its search box filters instructions rather than your documents.

The calendar provides shared notes, appointments, and deadlines when your installation enables it. Missing navigation items or actions may reflect your assigned role.

Upload and organize documents

  1. Open the destination folder and choose Add document, or use the folder's drag-and-drop upload area when available.
  2. Select the file and enter a clear document name. Add a comment, keywords, categories, and any required attributes.
  3. Choose reviewers, approvers, or a workflow if your installation requires them, then submit the form.
  4. Open the saved document to check its version and status. A document awaiting review may not be released immediately.

Use the multiple-document upload screen for a batch of files. Folder permissions, your storage quota, PHP upload limits, and the web server's request limit can affect uploads.

To replace an existing file while keeping its history, use Update document on that document. Uploading another document creates a separate item.

Versions, downloads, and document locks

Open a document and choose Download beside the version you need. Use Update document to upload a revision. Previous versions remain in the history unless an authorized user removes them.

Use Lock before editing when you need to reserve the document. Release the lock when finished. If another user holds it, ask that user or your administrator to unlock it before you upload a revision.

Where Document AI is enabled, open Compare versions, choose two versions of the same document, and submit the comparison. This compares extracted text; formatting and tracked changes are not compared.

The circular-arrow action beside a file in a folder is Index for search. Hover over or focus the button to read its label. It builds the semantic search index for that document; it does not refresh or replace the uploaded file.

Find documents with search

The top search bar offers Documents, Full text when enabled, and AI search when configured.

  • Documents: search document names and metadata. Use the full-text search screen when full-text indexing is enabled for the installation.
  • Full text: find whole words inside locally indexed PDF, Word, and supported text files. All search words must appear; put a phrase in quotation marks to match its word order. Results include highlighted excerpts. This search does not need AI credentials or incur provider charges.
  • AI search: search the meaning of indexed document passages. Try a question or a descriptive phrase, such as “contracts with renewal terms.”

To set up local full-text search, enable it under Admin Tools → Settings → Site → Edition, open the Full-text indexing dashboard, and choose Queue existing documents / rebuild. Continue to the next batch if shown. Uploads and revisions are queued automatically while this setting is enabled.

Schedule /usr/bin/php /path/to/LetoDMS/utils/fulltext-worker.php --config=/path/to/LetoDMS/conf/settings.xml --limit=5 every minute. The updated AI worker also handles local full-text jobs if it is already scheduled; use one schedule. The dashboard shows worker activity, pending/completed/failed jobs, and reindex actions. Search results use the latest readable version only. Full-text OCR has its own settings and does not require the AI module.

Local indexing accepts up to 50 MiB per input file and 2 MiB of extracted text. Over-limit or unsupported files fail visibly instead of publishing a partial index. New installations and old Lucene installations need a new database index; no legacy Lucene dependency is required. See docs/FULLTEXT.md for details.

AI search needs an embeddings provider, an embeddings model, and successfully indexed documents. Enabling the option does not immediately index all existing documents. Use Index for search for an existing document or enable automatic processing for future uploads.

Only accessible indexed results are returned. After changing the embeddings model or provider, documents need indexing with the new configuration. An empty AI result does not mean a document is absent; try Documents search as well.

Use Document AI

Open a document and find the Document AI panel. The AI module must be enabled, a provider configured, and your role permitted to use it.

  • Ask AI: select a version and ask a question about its contents. Follow the source links and verify the answer against the document.
  • Summaries: view saved results, choose Summarize for an immediate request, or Queue analysis for background processing.
  • Compare versions: select the earlier and later versions to request a summary of textual changes.
  • Metadata: review proposed titles and keywords. Apply or dismiss supported suggestions explicitly; other extracted information remains advisory.
  • Duplicates: inspect matching files or similar documents. A candidate match does not delete or merge anything.

Summaries and answers can be incomplete or incorrect. Review suggestions before applying them, and retain the normal human review and approval process. Hosted AI features send the required query and document text to the configured provider.

Automatic analysis, OCR, and pending jobs

Administrators configure this under AI Assistant → Provider settings → Processing settings. Select an analysis provider, enable automatic queuing, and configure embeddings if uploads should also become available in AI search.

Queuing is separate from processing. New uploads and versions can remain pending until the scheduled worker runs. A server administrator should schedule the existing worker every minute:

* * * * * /usr/bin/php /path/to/LetoDMS/modules/ai-assistant/worker.php --config=/path/to/LetoDMS/conf/settings.xml --limit=5

Replace both paths for your installation. In a hosting control panel, put the PHP command in Command, not “Input to command.” Choose a custom schedule with all minutes, hours, days, months, and weekdays to run every minute. Hourly processing can leave uploads waiting nearly an hour.

Check Jobs & usage for worker activity, status, attempts, and error details. Administrators can retry failed jobs or cancel eligible queued jobs. A missing or deleted document version cannot be processed; cancel that job rather than repeatedly retrying it.

  • Text PDFs require pdftotext; older Word .doc files require antiword.
  • .docx extraction requires PHP ZIP and DOM. Text processing requires PHP mbstring.
  • Scanned PDFs require optional OCRmyPDF; supported image OCR uses Tesseract. Enable OCR and install the language packs you need on the server.
  • The web and command-line PHP environments both need the required extensions and permission to read document storage.

OCR and processing have file-size, text-size, image-size, and execution limits. An administrator can inspect job details when a document cannot be processed. Existing summaries do not prove the latest version is indexed with the current embeddings model.

Permissions and access

Two controls can affect an action: your role permits the feature, and the folder or document ACL permits access to that item. Having a feature permission does not grant access to every document.

  • No access: the item is unavailable.
  • Read: view or download accessible content.
  • Read/write: make permitted updates.
  • Full access: perform operations requiring full control, including permitted deletion.

Items may inherit permissions from their parent folder. Document ownership and administrator status affect access; workflow rules can additionally restrict a particular version. Ask your administrator to review both your role and the item's ACL when an action is missing.

Reviews, approvals, and status

  1. Open My Documents and find items awaiting your review or approval.
  2. Open the document and download the relevant version. Read it before making a decision.
  3. Use the available review, approval, or workflow action. Add a comment explaining your decision and submit.
  4. Check the resulting status and history on the document page.

Traditional review/approval lists and configured workflows can behave differently. A new revision may need another review. AI summaries and change comparisons help you prepare; they do not approve or release documents for you. Notifications depend on the installation's email configuration.

Account, light mode, and dark mode

In the modern Bootstrap interface, use the moon/sun button at the top of the page to switch between Dark mode and Light mode. On small screens the button shows only the icon; its accessible label describes the action.

Your choice is saved in this browser and applies to later pages and the sign-in screen. Until you make a choice, the interface follows your device's color preference. A different browser or device has its own preference. If browser storage is blocked, switching still works for the current page but may not persist.

Open the signed-in user menu and choose My account to update the profile fields your administrator permits. Change your password there when available. Your administrator may enforce password strength, expiration, or account restrictions. Legacy visual themes do not use the modern color-mode switch.

Administrator: configure hosted AI

  1. Install and enable AI Assistant under Admin Tools → Modules. Grant intended roles module.ai-assistant.access.
  2. Open AI Assistant → Provider settings → Add provider. Choose the company to populate supported endpoint defaults. Enter a stable provider ID, a friendly display name, and the provider's API key.
  3. Choose a compatible chat model. OpenAI model discovery is available through Load OpenAI models; you can also enter a model ID manually. A listed model may not support the configured API format or be enabled for generation in your account.
  4. Save the provider, then choose it under Processing settings. Configure a separate embeddings model and endpoint for AI search. Chat and embeddings models serve different purposes.
  5. Enable only the processing features you want, schedule the worker, and test with a small non-sensitive document.

API key storage requires PHP OpenSSL and a saved LetoDMS encryption key under Admin Tools → Settings → System → Authentication. Back up that encryption key securely. Changing it requires re-entering provider API keys. A blank provider key field retains an existing saved key where supported.

Hosted providers can charge for document processing, embeddings, and questions. Review provider billing and project limits. An HTTP 429 message reporting insufficient quota or inactive billing requires attention in the provider account. Waiting alone does not resolve missing credits. Other 429 responses can be temporary rate limits.

Use Jobs & usage and processing settings to inspect requests and configure local request limits. Optional cost figures are estimates, not the provider's invoice. Enabling a provider does not verify billing or guarantee that a model is compatible.

Check for application updates

Open Admin Tools → Version information and choose Check for updates. The panel compares the installed version with published GitHub releases. Beta installations include prereleases by default; use the checkbox to change that selection. Results are cached for one hour. If your development build is newer than the published release, it will say so instead of recommending a downgrade.

The checker only reads public release information. Use its GitHub links to review release notes and downloads; installation remains manual. Publishing a branch commit or tag alone does not make an update available—you need to publish a GitHub Release.

Administrator: connect through WebDAV

The modern WebDAV endpoint uses SabreDAV; the old PEAR HTTP_WebDAV_Server package is no longer used. Install the dependencies in webdav/vendor/ and enable WebDAV under Admin Tools → Settings → System → Authentication.

Connect your WebDAV client to https://YOUR-SERVER/YOUR-LETODMS-PATH/webdav/index.php/, including the trailing slash, using native LetoDMS credentials. HTTPS and correct web-server routing are required. Administrators can connect; other users need webdav.access plus the relevant document permissions.

Uploading to an existing document creates a new version. Exclusive file locks expire after 30 minutes unless refreshed. HTTP 423 means the document is locked. HTTP 412 can mean the document changed since the client opened or locked it; reopen the current version before saving.

MySQL/MariaDB document tables must use InnoDB for DAV writes. An administrator can run php webdav/setup.php --config=/path/to/settings.xml --check to inspect storage readiness. Back up the installation and follow webdav/README.md before using the explicit migration command. SQLite uses its normal transactional storage.

Read-only mode, upload limits, document ACLs, and workflow access still apply. See webdav/README.md for server configuration, overwrite behavior, supported operations, and validation limits. Test desktop clients with disposable documents first.

Troubleshooting checklist

  • Upload fails: check file size, PHP/server upload limits, required metadata, folder write access, document locks, and your storage quota.
  • No Document AI panel: check that the module is enabled, a provider is configured, and your role has AI access.
  • AI search has no indexed results: check embeddings configuration, index the document, and inspect worker/job status. Try Documents search to find it by name.
  • Analysis stays pending: check the last worker activity. Automatic queuing needs a scheduled worker; it does not process jobs by itself.
  • PDF or Word text is missing: verify the server extraction tools. Image-only PDFs need OCR; unsupported or damaged files may fail extraction.
  • Provider request fails: review the displayed error, API key, endpoint, model compatibility, billing, and request limits. Do not paste API keys into support messages.
  • A saved setting seems unchanged: confirm it was saved, check configuration-file write permissions, and refresh the page after uploading changed application files.

When requesting support, include the action, document ID and version where relevant, error text, and job status. Keep credentials and confidential document content out of screenshots and logs you share.
